## 관리자 사용법

### 대량 전화걸기

1. 사업자유형, 지역, 업종, 발신 전화유형, 기업발굴유형을 선택합니다.
2. 최대 1,000건까지 요청 건수를 입력하고 발신 승인을 확인합니다.
3. 전화걸기를 누르면 서버가 조건과 현재 권한·담당·번호별 동의·수신거부·중복 여부를 다시 검사합니다.
4. 접수된 수, 부족한 수와 제외 사유를 확인합니다. 전화번호가 같은 업체도 한 번만 선택합니다.

**요청 1,000건은 1,000건의 연결 성공을 뜻하지 않습니다.** 실제 발신 가능한 업체만 접수하며 원천 공개번호 전체에 동의를 일괄 부여하지 않습니다. 현재 CRM에 배정되고 유효한 번호별 동의가 연결된 대상을 기준으로 선택합니다. 원천만 있는 업체는 관리자 설정에서 기존 전체 업체 목록으로 조회할 수 있습니다.

휴대폰/일반전화 필터는 원천에 해당 번호가 있는지가 아니라 **실제로 발신할 번호**에 적용됩니다. 동의받지 않은 다른 번호로 자동 교체하지 않습니다. 기존 설정의 평일 업무시간·일일 한도·동시 통화 1건을 유지합니다. 24시간이 지난 승인은 대기로 돌리고 결과보고에서 명시적으로 재승인합니다. 이 버전은 운영 일일 한도를 임의로 올리지 않습니다.

### 개별 전화걸기

1. 업체명, 사업자유형, 전화번호, 테스트/신규고객 안내 목적을 입력합니다.
2. 필요하면 대표자명, 지역, 업종, 주소를 추가합니다.
3. 해당 번호의 실제 안내 동의 또는 재연락 요청 근거와 유효기간을 입력하고 발신을 승인합니다.
4. 접수 후 결과보고에서 통화 결과를 확인합니다.

직접 입력한 정보는 별도 수동 대상 스냅샷에 저장합니다. 기존 CRM 업체를 만들거나 덮어쓰지 않으며, 가짜 company_uid를 생성하지 않습니다. 테스트 목적도 동의·수신거부 검사를 건너뛰지 않습니다. 내부 시험 모드에서는 서버 허용목록의 시험번호만 사용할 수 있습니다.

### 결과보고 / 관리자 설정

- 결과보고: 캠페인 진행, 일시정지/취소, 개별 결과, 방문 요청 확인, 만료 승인 재확인.
- 개별 결과와 수신거부/동의 철회 영역에서 마스킹 연락처와 요청시각을 확인해 같은 업체명의 요청도 구별할 수 있습니다. 원문 연락처를 노출하지 않습니다.
- 관리자 설정: 기존 전체 업체 100개 목록·선택, 동의 관리·수신거부, 연결 상태와 상담 예시 유지.
- 선택한 화면에 필요한 조회만 실행합니다. 첫 발신 화면 진입 때 전체 업체·캠페인 결과를 동시에 불러오지 않습니다.
- 일반 계정의 메뉴·직접 서버 접근 차단은 유지합니다.

## DB 변경 및 권한

다음 순서로 적용합니다. 앞선 v9.14.0~v9.14.3 스키마가 필요합니다.

1. `supabase/migrations/20261007051303_ai_visit_calling_simple_campaigns.sql`
2. `supabase/migrations/20261007051446_ai_visit_calling_manual_targets.sql`

- campaigns: `selection_filters`, `requested_count`, `request_fingerprint`, `selection_kind`.
- 새 manual_targets: 입력 스냅샷·작성 관리자·요청 식별키·동의 근거/기간·철회 이력, RLS 및 관리자/전화 인덱스.
- jobs: `target_kind`, `manual_target_id` 및 CRM/수동 상호배타 CHECK. 수동 대상에만 기존 CRM 참조 컬럼 NULL 허용.
- suppressions: 수동 대상의 company_uid가 NULL이어도 전화번호 기반 전사 수신거부 유지.
- 동일한 정규화 전화번호가 기존 CRM 업체 연락처에 있으면 해당 업체의 연락제외·카카오 수신거부·다른 번호의 차단도 검사합니다. 이름만으로 연결하지 않습니다. 이를 위해 CRM 연락처의 번호 정규화 부분 인덱스 1개를 추가합니다.
- 새 filtered/manual RPC, 공통 발신 전 확인 함수. 기존 worker/결과 조회/승인 함수는 양쪽 대상을 지원하며, 고객 행을 수정하지 않습니다.
- 요청 멱등성, 트랜잭션 잠금, 동일 번호·업체 중복 방지. 재클릭은 동일 작업을 반환하고 입력이 바뀐 같은 요청 키는 차단합니다.
- 새 테이블은 RLS 기본 거부, anon/authenticated 권한 없음, 서버 service_role만 접근합니다. 함수는 SECURITY INVOKER/빈 search_path, 활성 관리자 재검사를 사용합니다. 현재 CRM의 서버 인증 구조를 유지하며 공개 RPC 실행 권한을 열지 않습니다.
- 수동 입력 스냅샷은 수정 불가이며 동의 철회 메타데이터만 별도 허용합니다. 고객정보·통화결과를 삭제하지 않습니다.

## 실발신 전 필요한 별도 작업

앞선 배포 확인 시 실제 발신 플래그는 OFF, 하루 한도 1건, 전용 발신 worker/gateway가 없었습니다. 이 패치만 배포해도 실제 1,000통을 걸 수 있는 상태가 되는 것은 아닙니다.

이번 배포는 운영 고객 행을 복사하지 않고 운영 스키마만 임시 Supabase에 재현해 검증합니다. 최신 운영과 테이블 91개·컬럼 1,268개·함수 204개·제약 498개·인덱스 422개 및 관련 해시가 일치함을 확인했습니다. 검증 환경의 기존 자동 마이그레이션 실패는 누락된 초기 스키마 이력 때문이므로 운영을 수정하지 않고 스키마 전용 bootstrap으로 해결했습니다. 실제 발신 활성화·일일 한도 변경·유료 통화 시험은 별도 확인 후 진행합니다.
