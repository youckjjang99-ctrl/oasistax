# AI 방문상담 관리자 전용 전체 업체 목록 — v9.14.3

기준: `origin/main` `b9eb3eaa3754ace9ff53762c4939c46fab599d98`. 작성일: 2026-10-06.

## 변경 목적

기존 AI 방문상담은 담당 배정된 영업후보만 조회했습니다. 일반 계정에도 메뉴가 보였고, 업체명 검색은 현재 페이지에만 적용됐습니다. 이전 페이지에서 100개를 선택하면 다음 페이지의 전체선택이 무시되는 문제도 있었습니다.

이번 변경은 관리자 전용 접근, 전체 원천 업체 조회, 정보 보강 및 100개 단위 선택에 한정합니다. 전화망·OpenAI 모델·인증키·경정청구·전화번호 수집 작업은 수정하지 않습니다.

## 관리자 사용법

1. **AI 방문상담 → 업체 선택**에서 개인/법인/미확인, 연락처 유형, 지역, 업종, 발굴유형, 업체명 조건을 정합니다.
2. 검색 조건을 적용하면 전체 원천 범위에서 최대 100개가 표시됩니다. 원천에만 있고 아직 내 영업DB에 담지 않은 업체, 전화번호가 없는 업체도 기본 목록에 포함합니다.
3. 이전/다음으로 100개씩 이동합니다. 전체 건수 계산이나 전체 데이터 다운로드를 매번 실행하지 않습니다.
4. **현재 페이지 전체선택**은 앞서 선택한 업체를 현재 화면의 최대 100개로 교체합니다. 개별 체크와 선택 해제도 가능합니다. 검색 조건을 바꾸면 이전 선택과 페이지를 초기화합니다.
5. 업체명, 사업자 구분, 지역·주소, 업종, 고용인원·증감, 발굴유형, 휴대폰·일반전화, 발신 조건을 확인합니다. 없는 값은 0이나 추정값 대신 미확인으로 표시합니다.
6. 캠페인 저장 및 시작은 기존 동의·담당 연결·수신거부·중복 검사를 통과한 업체에만 가능합니다. 조회·체크·캠페인 초안 저장만으로 전화가 발신되지는 않습니다.

## 전체 목록과 발신 대상의 차이

전체 목록의 주 원천은 `oasis_employment_contacts`입니다. 여기에 대응 원천이 없는 기존 영업후보를 보충합니다. 원천 행 식별자와 전사 공통 `company_uid`를 구분하며, 이름만 같은 회사를 임의로 연결하지 않습니다.

원천 목록을 열거나 체크하는 것은 담당 배정이나 전화 안내 동의 등록이 아닙니다. 원천 업체가 발신 조건을 갖추지 못했다면 해당 사유를 표시합니다. 이 경우 기존 DB발굴의 내 영업DB 저장·담당 연결과 검증된 연락처·동의 확인 절차가 먼저 필요합니다. 이번 패치는 새 자동 배정이나 동의 추정 기능을 만들지 않습니다.

휴대폰/일반전화 검색 조건은 **보유 연락처 분류**입니다. 필터를 바꿨다고 실제 발신번호를 자동 변경하지 않습니다. 실제 발신번호는 기존 서버가 선택한 검증 연락처이며 해당 번호의 유효한 동의를 다시 검사합니다. 화면 연락처는 기존 정책대로 마스킹합니다.

사업자 구분은 가능한 경우 저장된 사업자등록번호의 구분코드를 사용합니다. 이름의 ‘주식회사’ 표시만으로 개인/법인을 확정하지 않습니다. 단체·공공기관 등 구분이 모호하거나 식별정보가 없으면 미확인입니다. 이 분류는 증명서 확인이나 사업자 상태 조회를 대신하지 않습니다. 구분코드 근거: [국세청 사업자등록번호 부여 체계](https://www.nts.go.kr/nts/na/ntt/selectNttInfo.do?mi=2448&nttSn=1386).

고용증가는 원천에 저장된 증감 신호입니다. 정책자금 지원 대상 확정이나 이번 달 실제 증가를 뜻하지 않습니다. 신규 신호와 고용증가가 함께 있을 수 있으며 비교 기준이 없는 행은 추측하지 않습니다.

## 권한과 데이터 보존

- 일반 계정: 메뉴 비노출, 직접 화면 진입 차단, 서버 RPC에서 현재 관리자 여부 확인.
- 화면 자동갱신 중 역할이 바뀌어도 서버 조회가 거부되면 목록과 선택을 지우고 후속 작업을 중단합니다.
- 기존 사용자용 voice/campaign RPC에도 관리자 조건을 적용합니다. 화면에서만 숨기는 방식이 아닙니다.
- 새 RPC는 service_role 전용, SECURITY INVOKER, 빈 search_path를 사용합니다. 익명·브라우저 인증 역할에 실행 권한을 부여하지 않습니다.
- 기존 원천/고객/연락처/배정/동의/통화/감사 행은 삭제·초기화·자동 병합하지 않습니다.
- 원천 업체 목록 조회는 읽기 전용입니다. 야간 수집의 `phone_status`, 공급사 단계, 시도 횟수, 전화번호, 갱신 시각을 변경하지 않습니다.
- 고정 원천 키로 다음 페이지를 찾습니다. 전화번호 수집으로 갱신 시각이 바뀌어도 페이지 정렬 키가 바뀌지 않습니다. 새 원천 삽입까지 한 시점의 스냅샷으로 고정하는 기능은 아니므로 최신 전체 탐색은 첫 페이지부터 다시 시작합니다.
- 실행 중인 worker/gateway와 이미 연결된 통화는 이번 화면 권한 변경으로 강제 종료하지 않습니다. 관리자의 화면 접근 차단과 통신사 통화 종료는 별개입니다.

## 적용·검증·롤백

별도 마이그레이션: `supabase/migrations/20261006093201_ai_visit_calling_admin_catalog.sql`. 기존 테이블·컬럼·고객 ID는 변경하지 않습니다. 전체 목록 RPC와 표시용 보조 함수, 기존 두 사용자 RPC의 관리자 검사만 추가합니다.

기본 페이지는 기존 인덱스와 고정 키를 활용합니다. 원천 전체에 대한 신규 대형 인덱스 빌드는 이 변경에 자동 포함하지 않습니다. 이름·업종의 포함검색 또는 결과가 거의 없는 복합 조건은 원천을 많이 읽을 수 있어 즉시 응답을 보장하지 않습니다. 지연 시 조건을 구체화해 다시 검색하고, 운영 튜닝은 저장공간·쓰기 부하를 검토해 별도로 적용합니다.

이 릴리스는 로컬 변경과 검증 결과를 먼저 제공합니다. 운영 Supabase 적용, GitHub push, Railway 배포는 별도 승인 후 수행합니다. 이전 릴리스의 임시 DB 비용 승인을 새 검증에 재사용하지 않습니다. 실제 전화·번호 구매·구독 결제도 진행하지 않습니다.

배포 전에 새 SQL을 격리 PostgreSQL/Supabase에서 두 번 적용해 멱등성·권한·페이지 조회를 확인하고 기존 원천/고객 건수와 비교해야 합니다. 변경된 UI는 새 catalog RPC가 없으면 안전하게 준비 미완료로 멈추므로, 승인 후 DB 마이그레이션을 먼저 적용하고 코드를 배포합니다.

`RUN_v9.14.3.bat`는 로컬 화면 실행용입니다. 발신 플래그를 OFF로 고정하며 DB 마이그레이션·worker 시작·배포를 실행하지 않습니다.

롤백 시 기존 데이터와 신규 함수를 삭제하지 않습니다. 문제가 발생하면 발신 OFF를 유지하고 AI 방문상담 접근을 잠시 중지한 후 코드만 이전 배포로 복구할 수 있습니다. 관리자 전용 서버 권한은 유지해야 합니다. 이전 UI가 일반 계정에 메뉴를 보여도 DB 작업은 거부돼야 합니다. 쿼리 개선이 필요하면 전진 수정 마이그레이션으로 함수만 교체하고 원천 자료나 통화 이력을 되돌려 덮어쓰지 않습니다.

실제 검증 범위·변경 파일·마이그레이션 이름은 동봉 CHANGELOG를 확인합니다.
