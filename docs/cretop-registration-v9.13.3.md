# v9.13.3 기업 식별정보·대표자 연락처 보완

기준: GitHub main `ebfdf365ab6b95ce5c7cdb74306777af199a860e` (2026-09-21).
별도 작업 브랜치: `codex/cretop-registration-20260921`.
기존 작업 폴더와 미배포 v9.14.0 패치는 수정하거나 합치지 않았다.

## 원인

- 크레탑 표지에서 PDF 내부 텍스트 순서는 시각적 배치와 달리 항목 제목들이 먼저,
  값들이 나중에 나올 수 있다. 운영 고정 버전 pypdf 5.9.0과 실제 21쪽 문서로 기존 오류를 재현했다.
- 기존 파서는 다음 줄의 `-사업자번호`를 업체명으로 허용했다. 대표자명도 다른 항목 값을
  이름으로 잘못 해석해 기업개요의 정상 대표자명과 충돌하고 공란 처리될 수 있었다.
- 표준산업분류의 명칭만 보존하고 괄호 속 코드·차수는 버렸다. 화면의 기존 `주업종코드`는
  종합소득세 신고서 파서에서 사용하는 별도 필드로, 표준산업분류 코드를 그대로 대입하면 안 된다.

## 변경 범위

- 업체명·대표자 후보에서 항목 제목과 표 머리글을 제외하고 정상 기업개요를 확인한다.
- 등록 직전에도 업체명이 항목 제목인지 검증한다. 정상적인 외국어·공동 대표 이름 지원은 유지한다.
- `표준산업분류코드`, `표준산업분류차수`를 추출·검토·저장·표시한다. 11차 근거를 우선하며
  기존 `주업종코드`는 별도 보존한다. 근거가 없는 세무 업종코드를 추정하지 않는다.
- `대표자 휴대전화`를 등록, 기존 고객 수정, 상세 조회, 검색에 연결한다.
  공개 연락처·대표전화·간편인증용 번호로 자동 복사하지 않는다.
- 대표자 휴대전화는 선택 입력이며 공란 입력으로 기존 번호를 자동 삭제하지 않는다.
  문자열로 저장해 앞자리 0을 보존하고 휴대전화 형식을 검증한다.
- 기존 고객의 수정은 기존 갱신 확인 절차를 거친다. ID, 원본, 메모, 이력, 재무자료를
  배포 시 일괄 수정하거나 삭제하지 않는다.
- 배포 전 추가 검토에서 새 컬럼 추가가 기존 Excel의 자동 변환을 유발하여 사용자 확장열과
  추가 시트가 소실될 수 있는 기존 저장 경로를 확인했다. 신규 필드 미존재만으로는 조회 시
  재작성하지 않으며, 저장할 때도 기존 워크북의 추가열·수식·주석·다른 시트를 보존한다.
  기존 행 대응을 확인할 수 없거나 파일을 읽지 못하면 빈 양식으로 대체하지 않고 저장을 중단한다.

## 데이터베이스와 영향

신규 테이블·컬럼·RPC·RLS 마이그레이션은 없다. 기존 고객 `customer_data` JSON과 고객DB의
확장 필드로 저장한다. 기존 사용자별 권한·소유자 검사와 클라우드 동기화 경로를 유지한다.
새 필드가 구형 Excel 양식이나 재조회 과정에서 누락되지 않도록 컬럼 및 문자열 타입을 보완한다.

전화번호 수집, 영업 배정, 경정청구·Tilko·인증 요청, 메시지 발송 경로는 변경하지 않는다.
없는 최근 3개년 재무자료는 생성하지 않는다. 출처·연도가 불명확한 재무가 있는 문서의
기존 ‘기본정보만 저장’ 검토 절차도 유지한다.

## 적용 후 사용법

1. 기업등록에서 PDF를 다시 분석한다. 분석만으로 기존 고객정보가 바뀌지는 않는다.
2. 업체명·대표자명·표준산업분류코드를 확인하고 대표자 휴대전화를 필요할 때 직접 입력한다.
3. 기존 사업자번호가 확인되면 신규로 중복 등록하지 않고 기존 기업 갱신에 동의한 후 저장한다.
4. 기존 고객은 CRM 기본정보 수정 화면에서도 대표자 휴대전화를 입력할 수 있다.
5. 기업정보 상세에서 표준산업분류와 세무 주업종코드를 별도 확인한다.

## 검증과 배포

- 운영 고정 버전 pypdf 5.9.0을 실제로 로드한 전체 회귀 테스트:
  `1501 passed, 92 subtests passed` (배포 전 보존 보완 포함, 34.26초).
- 실제 첨부 PDF를 별도 프로세스 분석기 → 기본정보만 저장 → 등록 검증 경로로 실행했다.
  업체명·대표자명은 기업개요와 일치하고, 표준산업분류 코드·차수·업종명도 원문과 일치했다.
  근거 없는 세무 업종코드나 대표자 휴대전화는 생성하지 않았다.
- 최근 3개년 재무행을 만들어 내지 않으며, 기본정보만 저장 경로의 재무 필드는 비어 있음을 확인했다.
- 표지 항목명 오인, 업체명 공란·머리글 차단, 대표자 충돌, 여러 줄 업종명과 다음 항목 경계,
  10차/11차 구분, 기존 재무 추출 경로를 합성 자료로 회귀 검증했다.
- 대표자 휴대전화 입력 위젯, 형식·국가번호 정규화, 기존 번호의 공란 덮어쓰기 방지,
  검색, Excel 앞자리 0 유지, 기존 세무 업종코드 보존을 검증했다.
- 기존 워크북의 최초 조회·휴대전화 수정·신규 등록·사업자번호 수정·레거시 시트 변환을 검증했다.
  확장열·수식·주석·다른 시트가 유지되며 빈 자료·행 축소·재정렬·중복 인덱스·읽기 실패 시
  원본 바이트와 수정시각이 변하지 않는다. 기존 구형 시트는 삭제하지 않고 별도 보존한다.
- 고객 JSON 전달·클라우드 복원은 외부 통신을 차단한 모의 저장소로 검증했다.
  운영 Supabase 쓰기와 실제 브라우저의 PC·모바일 종단간 검증은 수행하지 않았다.
- 개인정보 유입 검사와 `git diff --check`를 통과한 변경 파일만 패키징한다.
  전체 파일 목록은 `docs/cretop-registration-files-v9.13.3.md`에 기록했다.

실제 고객 PDF·전화번호·식별번호를 Git이나 패치 ZIP에 포함하지 않는다.
코드 준비 단계에서는 Git push·Railway 배포·운영 고객 수정을 수행하지 않았다.
2026-09-21 사용자 배포 승인 후 추가 보존 검증, GitHub 검사와 운영 배포 상태를 확인한다.
승인은 코드 배포에 한하며 운영 고객정보의 일괄 갱신·삭제는 수행하지 않는다.

## 롤백

이 패치만 적용한 소스 릴리스를 직전 정상 릴리스로 되돌린다. 새 필드에 저장된 고객정보는
삭제하지 않는다. 이전 코드의 고정 컬럼 저장 경로는 새 필드를 누락시킬 수 있으므로,
롤백 중에는 고객정보 편집을 중지하고 확장 필드 보존을 확인한 후 다시 허용한다.
운영 데이터 일괄 되돌리기나 폴더 전체 교체, Git 이력 삭제를 사용하지 않는다.
