## 원인과 수정

1. 이미지형 기업개요에서 기본 OCR 방식이 표 안의 라벨과 값을 누락해도 업체명이 있으면 대체 OCR를 실행하지 않았다. 표 행 보존 방식으로 재시도하고 대표자·법인번호·설립일 등 유효 필드 충족도를 비교한다. 재시도 실패 시 원래 결과는 보존한다.
2. 대표자명 검색이 문서 뒤쪽의 거래처 표 제목을 사람 이름으로 선택할 수 있었다. 재무/거래 표 제목을 제외하고 유효한 표지/개요의 대표자 값을 탐색한다.
3. 인증표는 항목 5개 다음 줄에 상태 5개를 표시한다. 기존의 '항목 바로 뒤 상태' 규칙을 보완해 항목과 상태의 수가 일치할 때 열 순서로 매핑한다. 누락/모순은 미확인으로 남긴다.
4. 파란 캡슐 테두리 때문에 OCR가 내부 글자도 그림으로 버렸다. 인증표가 불완전한 경우에만 임시 OCR 이미지의 큰 파란 테두리를 제거해 재인식한다. 다섯 항목이 모두 명시적으로 확인된 경우에만 인증 근거로 채택하며, 기본정보·재무 본문은 교체하지 않는다. 원본 PDF는 수정하지 않는다.
5. 구형 고객 양식과 기본 저장 열에 법인번호·기업유형·규모 등이 빠져 저장 시 유실되었다. 필수 열을 보충한다. 인증 미확인은 N으로 변환하지 않고 공란으로 보존하며 재분석에서 기존 인증을 지우지 않는다.
6. Excel 재저장 시 식별번호 선행 0 손실과 설립년도 정수/문자 타입 충돌을 방지한다.

## 검증

- 사용자 첨부 25쪽 이미지 PDF 로컬 전체 처리 세 차례: 약 23~29초, 25/25쪽, OCR 경고 없음.
- 대표자명 표지 일치, 13자리 법인번호, 설립일·기업유형·기업규모 추출 확인.
- 인증 상태 5개가 원문 표시와 일치. 이노비즈·메인비즈는 Y.
- 종업원수는 원문 공란이므로 미확인 유지. 외부 인원수나 인증정보를 임의 생성하지 않음.
- 합성 회귀 테스트로 잘못된 대표자 헤더, 가로 인증표, 불완전/모순 인증표, OCR 실패, 보조 OCR의 재무 오염 방지, 구형 양식/Excel round-trip/기존 인증 보호를 검증한다.
- 실제 고객 PDF, 추출 JSON 및 이미지/식별번호는 Git에 포함하지 않는다. 로컬 `tmp/` 진단 결과만 사용한다.
- 최종 전체 회귀: `1256 passed, 92 subtests passed` (25.09초). 개인정보 유입 검사·diff 검사 통과.
- 독립 검토 후 보완: OCR 후보의 다른 회사 식별자 채택 거부, 기존/보조 인증 판정 충돌을 미확인으로 처리, 상태 값 사이의 비관련 본문 거부, 일반 누락 스칼라가 기존 값을 지우는 경로 방어. 고객정보 없는 합성 회귀 테스트를 포함한다.

## 적용 후 사용법

같은 PDF를 다시 분석하고 기본정보·인증 추출값을 검토한다. 이미 저장된 기업은 기존 기업 갱신 확인 절차를 통해 반영한다. 이번 패치는 기존 저장된 잘못된 값을 자동으로 대량 수정하지 않는다. 종업원수 등 원문에 없는 값은 별도 확인 후 입력한다.

## 롤백 및 제한

운영 반영 전 검토된 변경 파일만 배포한다. 문제가 있으면 이 기능 패치만 revert하여 이전 코드를 복원한다. 데이터베이스/Storage 롤백이나 고객정보 삭제는 필요하지 않다. 새로 보존한 열을 기존 고객 파일에서 제거하지 않는다.

OCR은 모든 레이아웃의 정확도를 보장하지 않는다. 불완전 인증은 미확인으로 표시하며 원문 확인이 필요하다. 실제 운영 UI 저장·기기 간 조회는 배포 후 별도 스모크 검증 대상이다. 고객 데이터 갱신은 사용자 확인 후 진행한다.

## 패치 및 업로드

ZIP은 위 변경 파일 8개만 기존 상대 경로대로 포함하며 상위 폴더·고객 자료·`.git`은 포함하지 않는다. 최신 main 기반의 깨끗한 작업 폴더에 적용하고, 기존 변경과 겹치면 먼저 비교한다. `RUN_v9.13.1-cretop-company-fields.bat`는 로컬 검증만 수행한다.

사용자 배포 승인 후 최신 main과 충돌을 확인하고 적용한다. 아래 명령은 이 패치 외 변경이 없는지 검토한 뒤 사용한다. 이번 작업에서는 실행하지 않았다.
