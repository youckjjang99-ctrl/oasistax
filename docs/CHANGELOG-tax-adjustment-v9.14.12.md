# OASIS 세무조정계산서 업로드와 주가평가 연동

버전: `v9.14.12-tax-adjustment`

작업일과 법령 확인일: 2026-10-22 Asia/Seoul

기준 소스: GitHub main `a5751e5958763ea258fc55985205f82a34fc99e4`

상태: 로컬 구현과 가상 자료 회귀 검증 완료. 운영 DB 적용, GitHub 업로드와 Railway 배포는 실행하지 않았습니다.

## 원인과 변경 내용

기업 첨부자료의 공통 업로더가 단일 파일만 받아 여러 연도·분할 세무조정계산서를 한 번에 등록할 수 없었습니다. 기존 진행 안내를 다중 처리에 연결하고, 화면 재실행 후에도 파일별 결과가 남도록 보완했습니다. 주가평가에는 첨부 세무조정계산서의 출처를 확인하고 법정 순손익액으로 연결하는 검토 경로가 없었습니다.

- 세무조정계산서와 같은 공통 업로더를 사용하는 인정서 자료는 한 번에 최대 20개, 파일당 50MB, 합계 200MB를 처리합니다.
- 파일 확인, 페이지별 문자 인식, 항목 분석, 기업 연결 단계를 표시합니다. 파일별 등록 완료·검토 필요·실패·동일 내용 중복 제외 결과를 유지합니다.
- 한 파일이 실패해도 앞서 등록한 파일은 유지하고 다음 파일을 처리합니다. 다른 기업의 사업자등록번호가 확인되면 잘못 연결하지 않습니다.
- 기존 비공개 파일 보관과 고객 히스토리를 사용합니다. 원본과 분석이력의 클라우드 저장을 모두 확인한 경우에만 클라우드 완료로 표시합니다. 로컬 보존·클라우드 확인 필요 상태는 구분합니다.
- 동일 원본 재분석은 원본 파일을 재사용합니다. 분석 내용이 달라지면 새 분석 버전의 히스토리를 남기며 기존 히스토리는 삭제하지 않습니다.
- 다른 기기에서 더 최근에 분석한 이력을 해당 기업의 기존 로컬 원본과 함께 읽을 수 있습니다. 이 원격 조회는 새 반영 화면을 열 때만 수행합니다.
- 주가평가에 `세무조정계산서 반영` 세부 탭을 추가했습니다. 연도별 추출 근거와 충돌을 검토한 뒤 순손익액·해당 연도 주식수를 계산 탭으로 반영합니다.

## 세법 반영 범위

새 연동은 비상장주식 보충적 평가에 쓰는 순손익액의 검토·반영 기능입니다. 각 사업연도 소득금액에 법정 가산·차감과 특수 조정을 반영하며, 과세표준·회계상 당기순이익·법인세비용을 법정 순손익액으로 대체하지 않습니다. 차감세액에는 해당 외국법인세액·감면액·농특세·지방소득세도 검토하도록 안내합니다. [상속세 및 증여세법 시행령 제56조](https://www.law.go.kr/법령/상속세및증여세법시행령/제56조)

- 최근 3개 연속 사업연도, 평가일 직전 결산연도, 동일 결산일과 연도 말 발행주식수를 확인합니다. 결손인 개별 연도의 음수 순손익액은 보존하고 기존 3:2:1 가중평균 계산에 전달합니다.
- 공란은 0원으로 간주하지 않습니다. 원문에 항목·연도·단위가 확인되지 않거나 동일 연도 금액이 충돌하면 검토 없이 자동 확정하지 않습니다.
- 증감자 조정액 또는 일시환입 안분액이 있으면 전문가 검토 근거, 별도로 확정한 최종 순손익액·환산주식수와 구성항목 합계 일치를 요구합니다. ‘특수 조정 없음’ 선택으로 우회할 수 없습니다.
- 1년 미만·초과 사업연도와 결산일 변경 사례는 자동 반영하지 않습니다. 연환산 및 증감자·주식수 환산은 해당 규정에 따른 별도 검토 후 기존 수동 계산 경로를 사용합니다. [시행규칙 제17조의3](https://www.law.go.kr/법령/상속세및증여세법시행규칙/제17조의3)
- 이 연동은 확인한 현행 시행령 시행일인 2026-10-01 이전 평가나 미래 평가일에는 적용하지 않습니다. 법령 확인일 이후의 평가에는 법령 변경 여부를 다시 확인하도록 요구합니다.
- 과거 결산 재무상태표의 자산·부채는 참고로만 표시합니다. 평가일 현재 재산평가와 부채 조정이 필요한 순자산가액을 자동 덮어쓰지 않습니다. [시행령 제55조](https://www.law.go.kr/법령/상속세및증여세법시행령/제55조)

시가 우선 여부, 순자산가치만 적용하는 예외, 최대주주 할증·제외 요건과 개별 자산 평가는 기존 계산 화면에서 별도로 검토해야 합니다. 이번 연동이 모든 회사·평가일의 신고용 최종 주식가치를 자동 확정하지는 않습니다.

## 사용 방법

1. 기업정보등록에서 기존 기업을 선택하고 자료 종류를 `세무조정계산서`로 고릅니다. 여러 연도나 분할 파일을 함께 선택합니다.
2. `파일 분석·등록`을 누르고 진행 카드와 파일별 결과를 확인합니다. 검토 필요나 실패 파일은 원본을 확인합니다.
3. 해당 기업의 주가평가 계산 탭에서 평가기준일과 최근 3개 사업연도를 설정합니다.
4. `세무조정계산서 반영` 탭에서 반영할 연도를 선택합니다. 추출 근거와 법정 항목, 사업연도, 연도 말 주식수를 검토합니다. 해당 없음은 원문 확인 후 0을 명시합니다.
5. 증감자 등 특수 조정이 있으면 전문가 확정값과 근거를 추가합니다. 미확인 항목과 충돌을 해결한 뒤 `검토한 순손익액·주식수 반영`을 누릅니다.
6. 계산 탭에서 순자산 등 나머지 요건을 검토하고 재계산한 뒤 `평가자료 저장`을 누릅니다. 반영 근거·원본 식별자·검토자·변경 전 입력값을 기존 평가자료와 함께 보존합니다.

업로드만 하거나 반영 버튼만 누른 상태를 평가자료의 클라우드 저장 완료로 표시하지 않습니다.

## 데이터와 기존 기능 영향

Supabase 테이블·컬럼·인덱스·RLS 변경은 없습니다. 마이그레이션 SQL도 필요하지 않습니다. 기존 소유자 범위의 고객 히스토리와 비공개 파일 보관을 재사용합니다. 고객 ID, company_uid, 기존 원본·메모·평가자료를 삭제하지 않습니다. 기존 수동 주가평가와 영업권 계산은 유지합니다.

전화번호 수집기, 전사 영업배정, 경정청구 자료수집 API·문서 종류·인증 절차·Tilko 호출 로직은 수정하지 않습니다. 새로운 외부 AI 호출과 유료 전화 발신도 추가하지 않습니다.

- 기존 기업등록, 업로드 안내, 주가평가·영업권·등기 연동, Storage, 메뉴 성능 회귀

## 롤백과 배포 승인

이 기능 적용 전 코드 커밋으로 되돌려 배포합니다. 원본 파일·고객 히스토리·추가된 분석 버전과 기존 평가자료는 삭제하지 않습니다. DB 역마이그레이션은 없습니다. 구버전 코드는 새 반영 근거 필드를 사용하지 않으므로 고객 데이터가 아니라 코드만 되돌립니다.

운영 배포는 별도 승인 후 진행합니다. 공개 GitHub에 소스를 올릴 때는 아래 9개 변경 파일만 검토·추적하고 고객자료를 포함하지 않습니다. main 연결 Railway 서비스는 함께 재배포될 수 있습니다.

```bash
git status
git add enterprise_documents.py stock_valuation.py tax_adjustment_valuation.py tests/test_enterprise_document_batch.py tests/test_stock_tax_adjustment_ui.py tests/test_tax_adjustment_valuation.py VERSION.txt RUN_v9.14.12-tax-adjustment.bat docs/CHANGELOG-tax-adjustment-v9.14.12.md

```

위 명령은 검토된 변경만 있는 최신 main 작업 폴더에서 실행하는 예시입니다. 현재 작업 브랜치는 `codex/tax-adjustment-stock-20261022`이며, 이 브랜치의 검증된 커밋을 main에 반영하는 절차는 배포 승인 후 수행합니다.
