# v9.14.4 — AI 방문상담 간단 발신·개별 입력

2026-10-07 / 사용자 배포 승인, 로컬 및 격리 호스팅 DB 검증.

## 변경

- 기본 화면을 5개 필터·전화할 건수·발신 승인·전화걸기로 단순화했습니다. 조건에 맞는 최대 1,000개 업체를 서버에서 선택합니다.
- 별도 개별 전화걸기에 업체명·사업자유형·연락처·테스트/신규고객 안내 목적과 선택 기업정보를 입력합니다. 수신 동의 근거·유효기간·발신 승인을 명시적으로 확인합니다.
- 결과보고와 관리자 설정을 별도 화면으로 분리하고 선택한 화면만 조회합니다. 기존 전체 업체 목록·선택·동의·수신거부·캠페인 관리·대화 예시를 보존합니다.
- 배치/수동 요청 멱등성, 동일 업체·전화번호 중복 차단, 변경된 번호/담당 차단, 트랜잭션 내 접수+승인, 부족 건수·사유 표시를 추가했습니다.
- 수동 입력은 불변 스냅샷으로 분리하며 기존 CRM 업체·배정·ID·company_uid를 덮어쓰거나 가짜 ID를 만들지 않습니다.
- 기존 업체의 회사 단위 수신거부를 수동 번호 입력으로 우회하는 경로를 독립 검토에서 발견·재현하고 차단했습니다. 같은 정규화 연락처로 연결된 기존 업체의 거부 상태까지 확인합니다.
- 승인 24시간이 지나면 미발신 작업은 취소/삭제하지 않고 승인 대기로 돌아갑니다. 발신 재개는 명시적 재승인 후 가능합니다.
- 실제 발신 OFF, 시험번호 허용목록, 일일 한도, 동시 통화 한도, 불명확 발신의 자동 재시도 금지를 유지했습니다.
- 개별 결과와 수신거부/동의 철회 영역에 마스킹 연락처 및 요청 시각을 표시해 같은 업체명의 서로 다른 번호를 구별합니다. 원문 전화번호 fallback은 사용하지 않습니다.

위 SQL 수치는 로컬 인메모리 PGlite PostgreSQL 검증입니다. 신규 배치 합성 1,000건의 최신 로컬 누적 검증에서 약 **7.9초**가 관측됐습니다. 호스팅 검증은 아래에 구분했습니다. 두 결과 모두 운영 응답시간·동시 요청 성능을 보장하지 않습니다.

처음 전체 Python 실행의 6개 실패는 관리형 작업 폴더 내 합성 `user_data` 작성의 파일권한 제한이었습니다. 원본 폴더에 쓰기 권한을 확대하거나 고객정보를 바꾸지 않고, 테스트 프로세스의 `utils.USER_DATA_DIR`만 새 임시 디렉터리로 격리하여 **전체 1,914개를 재실행·통과**했습니다. 의존성 폐기 예정 경고 397개는 기존 FastAPI/Starlette 관련입니다.

UI 57개와 launch 53개 부분 검증은 전체 Python 수치에 포함되므로 중복 합산하지 않았습니다. 동일 번호 수신거부·서명·미디어 경로에 NULL CRM ID를 주입한 별도 mock gateway 5개도 통과했습니다. 실제 연락처·운영 행은 테스트에 복사하지 않았습니다.

배포 직전 독립 검토에서 마스킹 대상 식별 테스트 2개를 추가했습니다. 전체 재실행 도중 기존 WebSocket 종료 테스트에서 `provider.hung_up`이 빈 상태인 간헐 실패를 발견했습니다. Starlette 가상 클라이언트가 close 수신 직후 정리 task를 취소하는 순서를 유도해 동일 실패를 재현했습니다. gateway 운영 코드는 변경하지 않고 합성 provider의 `threading.Event`를 사용해 클라이언트 생명주기 안에서 종료 완료를 기다리도록 테스트만 보완했습니다. 실제 hangup이 없으면 5초 후 실패하며 원래 검증 조건은 유지합니다.

최종 전체 재실행은 **1,916개 통과 / 기존 경고 397개(56.46초)**입니다. 두 게이트웨이 파일 **101개**가 일반 실행 및 강제 close 순서 실행에서 통과했습니다. 대표 종료 경로 **100라운드·총 200회**도 통과했고, hangup을 고의로 생략한 두 대조군은 Event 검사에서 실패해 누락을 숨기지 않는 것을 확인했습니다. 추가 검사 수는 전체 테스트 수와 중복 합산하지 않습니다.

## 미실행 및 제한

- 원천 고객자료 변경·실제 전화·유료 음성 API 호출은 이번 배포 범위에 포함하지 않습니다.
- 격리 DB의 마이그레이션 2회 적용·합성 데이터 검증은 완료했습니다. 실제 호스팅 REST 시간제한 강제 발생·다중 연결 경합·운영 규모 부하 검증은 수행하지 않았습니다.
- 기존 클라우드 클라이언트의 기본 대기시간 20초가 신규 배치 RPC의 30초 제한보다 짧습니다. 응답 대기 중 시간초과가 나도 서버에서 저장됐을 수 있으므로, 동일 입력·동일 요청 키로 재확인하도록 안내합니다. 새 요청을 만들어 무조건 재발신하지 않습니다.
- 현재 발신 OFF/일일 1건/전용 worker·gateway 미구성 상태를 이번 변경으로 자동 해제하지 않습니다. 실제 통화 연결에는 별도 준비가 필요합니다.
- 유효한 번호별 동의와 CRM 배정이 없는 원천 업체는 대량 발신 대상이 아닙니다. 검색/조회 기능은 기존 전체 업체 목록에 유지됩니다.
- 일일 한도를 높이지 않으므로 1,000건 접수가 하루 1,000통 발신을 보장하지 않습니다. 만료된 잔여 요청은 재승인이 필요합니다.
