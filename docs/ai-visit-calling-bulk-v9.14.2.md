# AI 방문상담 대량 발신 대시보드 v9.14.2

## 적용 범위와 현재 상태

최신 `origin/main`의 `ccb9e00`을 기준으로 기존 v9.14.1 ClawOps/OpenAI 패치를 보존하면서 대량 발신 운영 화면을 추가합니다. 새 런타임 의존성은 없습니다. 기존 고객 ID, 배정, 연락 이력, 전화번호 수집, 경정청구 및 Tilko 호출은 변경하지 않습니다.

코드는 **ClawOps 전화망 → 자체 음성 gateway → OpenAI Realtime API** 방식입니다. ClawOps 관리형 AI 에이전트를 생성하는 방식이 아닙니다. 음성 입출력과 대화는 서버의 OpenAI 키를 사용합니다. API 키와 전화서비스 이용조건 확인, 운영 배포 및 실제 전화 품질 검증은 별도 절차입니다.

2026-10-06 사용자 배포 승인 후 격리 Supabase 검증과 운영 DB 마이그레이션 적용을 완료했습니다. 코드 배포 상태는 커밋별 Railway 결과로 확인합니다. 서버 키 등록과 회선·실통화 검증은 별도이며, 발신은 기본 OFF입니다. 이 문서만으로 실제 전화 운영 준비가 완료되었다고 판단하면 안 됩니다. 번호 구매·구독 결제·실제 발신은 수행하지 않았습니다.

## 사용자 흐름

1. CRM의 **AI 방문상담** 화면에서 내 영업DB 대상을 확인합니다. 일반 계정은 현재 본인이 담당한 업체만 접근합니다.
2. 체크박스로 업체를 선택하고 발신 묶음(캠페인)을 생성합니다. 다른 페이지의 선택도 유지하며 선택 해제가 가능합니다. 1회 생성 한도는 관리자 100개, 일반 계정 30개입니다.
3. 서버에서 동의 근거, 현재 담당자, 수신거부, 중복 요청, 최근 통화 및 방문·재연락 요청을 다시 검사합니다. 제외된 항목은 고정 사유 코드로 안내합니다. 화면에서 체크했다고 발신 가능한 상태가 되는 것은 아닙니다.
4. 관리자가 연결 준비 상태와 선택한 캠페인을 확인한 후 **일괄 승인/시작**합니다. 일반 사용자는 시작 승인 권한이 없습니다.
5. 별도 worker가 평일 한국시간 09~18시 안에서 하루 한도와 동시 1통 제한을 지켜 순차 발신합니다. 브라우저를 닫아도 서버 worker가 실행 중이면 계속 처리합니다.
6. 진행 현황에서 승인 대기·발신 대기·통화 중·종료·실패·결과 확인 필요·방문 요청을 확인합니다. 실패와 결과 불명 건은 자동 재발신하지 않습니다.
7. 일시정지는 **다음 발신을 차단**하는 기능입니다. 이미 연결된 통화를 즉시 끊지 않습니다. 취소는 남은 대기 요청을 취소하고 진행 중/완료 이력을 보존합니다.
8. AI가 받은 방문 희망은 담당자가 확인한 후 확정합니다. 고객의 수신거부는 이후 발신 대상에서 제외됩니다.

캠페인 작업과 기존 건별 요청을 분리해 관리합니다. 캠페인 일시정지를 기존 건별 승인 화면으로 우회할 수 없도록 서버 worker가 실행 상태를 재확인합니다. 담당자가 바뀌면 이전 담당자는 캠페인을 이용해 업체 상세 결과에 접근할 수 없습니다.

### 화면 수치 해석

- 통화 종료는 통신 종료 건수이며 방문 예약 성공을 뜻하지 않습니다.
- 방문 요청은 고객 의향 접수 건수로, 사람의 확정 절차와 구분합니다.
- 불명확한 통신사 응답은 `결과 확인 필요`에 남습니다. 동일 번호에 재발신하기 전에 통신사 기록을 확인해야 합니다.
- 캠페인 생성 한도와 일일 발신 한도는 별개입니다. 100개를 선택해도 일일 한도가 20이면 그날 최대 20개만 처리합니다.
- 시작 승인은 24시간만 유효합니다. 하루 한도 등으로 남은 요청을 계속 처리하려면 만료 전에 관리자가 다시 검토·승인해야 합니다. 이미 만료되어 작업자가 취소한 요청은 이력을 보존하며, 대상 상태를 재검토한 뒤 새 캠페인으로 접수합니다. 여러 날 무제한 자동발신하는 기능이 아닙니다.
- 화면의 준비 완료는 환경설정 검사 결과이지 실통화 품질·결제 잔액을 보장하는 표시가 아닙니다.

## Supabase 변경

다음 두 신규 마이그레이션을 순서대로 적용하는 패치입니다. 이전에 적용한 원본 SQL 파일은 수정하지 않습니다.

1. `supabase/migrations/20261003010404_ai_visit_calling_clawops_provider.sql`
   - 기존 `oasis_voice_jobs`에 통신사 구분 및 시험 범위 보호. v9.14.1 안내서 참조.
2. `supabase/migrations/20261006081850_ai_visit_calling_bulk_campaigns.sql`
   - `oasis_voice_campaigns`: 발신 묶음의 생성자, 이름, 요청 멱등키, 상태, 생성 결과, 생성/수정 시간.
   - `oasis_voice_jobs.campaign_id`: 기존 작업은 NULL을 유지하는 선택적 외래키와 인덱스.
   - 캠페인 생성·목록·집계·작업 조회·일괄 시작·일시정지·취소용 서버 RPC.
   - 동시 생성/승인은 기존 발신 대기열 트랜잭션 잠금과 중복 차단을 재사용합니다.
   - 신규 테이블은 RLS와 service_role 전용 접근을 사용합니다. CRM의 커스텀 계정/현재 배정 권한을 RPC 안에서 검증합니다. 일반 브라우저용 키로 직접 RPC를 호출할 수 없습니다.
   - 고객 원천 테이블이나 파일은 삭제·초기화하지 않습니다. 캠페인 취소에도 통화·감사 이력은 남습니다.

2026-10-06 격리 Supabase에서 각각 두 번 적용하고 역할/RLS/기존 RPC를 검증한 후 운영에 적용했습니다. 상세 결과와 건수 비교는 CHANGELOG를 확인합니다. 이 검증은 전화서비스 인증·네트워크·음성 왕복 검증을 대체하지 않습니다.

## 연결 준비와 안전한 점검

환경변수 목록, ClawOps 서명키/번호 설정, 과금 확인 질문은 [v9.14.1 연결 안내](ai-visit-calling-clawops-v9.14.1.md)를 함께 읽습니다. 키는 Railway의 비밀 환경변수에 저장하고 Git·대화·스크린샷에 넣지 않습니다.

설정값을 출력하지 않는 오프라인 검사:

```sh
python -m voice_calling_preflight
# 같은 검사, worker의 대기열 클레임/발신 없음:
python voice_calling_worker.py --check-only
```

OpenAI 모델 메타데이터만 읽는 선택적 네트워크 검사:

```sh
python -m voice_calling_preflight --check-network
```

이 검사는 고정 OpenAI HTTPS 주소에 GET만 요청하며 실제 통화, 유료 Realtime 세션, DB 쓰기를 하지 않습니다. 모델 조회 성공도 실시간 음성 사용권한·잔액·품질 검증 완료를 뜻하지 않습니다. 공급사 계정, gateway 연결, DB 스키마, 실제 음성 왕복은 별도로 표시합니다.

### 운영 서비스 구성

- CRM: 기존 Streamlit 서비스 유지.
- 음성 gateway: 별도 HTTPS/WSS 서비스, `uvicorn voice_calling_gateway:app --host 0.0.0.0 --port "$PORT" --no-access-log --ws-max-size 131072`.
- 발신 worker: 별도 상시 실행 서비스. 승인된 운영 설정에서만 `python voice_calling_worker.py` 실행. 처음에는 동의받은 내부 시험번호 1개·일일 1건으로 검증합니다.
- DB: 기존 Supabase의 권한 제한 RPC/대기열 사용. CRM에서 대상을 선택하는 것만으로 PC 프로세스가 직접 전화를 걸지 않습니다.

**고객 발신을 켜기 전 필수 조건:** 외부 스트림 과금 서면 확인, 운영 반영 승인, 키/070 번호 등록, gateway ingress의 공급사 IP/연결 제한 검증, 양방향 한국어·끼어들기·수신거부·최대시간 종료·방문 희망·실청구액 내부 통화 확인. 관리형 AI/외부 스트림 추가 비용은 아직 확인되지 않았으므로 확정 비용을 제시하지 않습니다.

## 데이터·안전 영향

- 기존 동의 근거/수신거부/담당자 검증은 유지합니다. 공개 연락처라는 사실만으로 동의를 자동 등록하지 않습니다.
- 동시 1통과 하루 최대 100건 상한은 이번 패치에서 올리지 않습니다. 더 큰 물량은 공급사 조건, 비용, 인입 응대 여력을 확인한 후 별도 변경합니다.
- 공급사 발신 응답 뒤 DB 기록이 실패하면 알려진 통화는 종료를 시도하고 결과 불명 상태로 격리합니다. 오류 때문에 반복 발신하지 않습니다.
- 고객 상담 데이터와 인증 키를 진단 화면/로그에 출력하지 않습니다. 실제 녹음·전체 전사를 앱에서 저장하지 않으며 공급사 별도 보관 설정은 확인이 필요합니다.

## 롤백과 운영 승인

1. 발신 활성화 플래그를 OFF로 바꾸고 worker를 중지합니다.
2. 통신사에서 진행 중 통화 종료 여부를 확인합니다. 캠페인 일시정지만으로 이미 연결된 통화가 종료되지는 않습니다.
3. 이전 코드 배포로 되돌리되 신규 캠페인/작업/감사 테이블과 컬럼은 삭제하지 않습니다.
4. **캠페인을 모르는 이전 worker를 즉시 재가동하면 안 됩니다.** 일시정지된 캠페인의 approved 작업까지 가져갈 수 있으므로, 서버 관리자 절차로 남은 캠페인 요청을 취소/검토하고 통화 불명 건을 정리한 뒤 재가동 여부를 결정합니다.

`RUN_v9.14.2.bat`는 발신 OFF 로컬 화면 실행용이며 마이그레이션·배포·worker 실행을 하지 않습니다. 변경 파일만 포함된 패치는 `.git`과 고객정보를 덮어쓰지 않습니다. 실제 운영 적용과 GitHub push/Railway 배포는 결과 검토 후 승인을 받아 진행합니다.
