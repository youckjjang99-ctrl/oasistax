# v9.13.2 크레탑 대표자 검증·재무 부호 보완

## 기준·변경 범위

- 최신 main `fec9252` 기반 별도 worktree에서 수정. 원래 작업 폴더의 미커밋 변경은 보존.
- 사용자가 대표자명/음수 금액 확인 후 수정·재배포를 승인한 범위. 기존 고객을 자동으로 수정하지 않는다.
- Supabase 테이블·컬럼·RLS·SQL 변경 없음. 원천 DB·전화번호 수집·경정청구/Tilko·인증 API는 변경하지 않는다.
- PDF 분석은 로컬 OCR이며 유료 수집 API를 호출하지 않는다. 실제 고객 PDF·추출문·번호·이름은 Git/테스트에 넣지 않는다.

## 원인과 보완

1. 기존 최신 금액 정규식은 빈 이전연도 셀의 `-`와 다음 양수 금액 사이 공백을 음수 부호로 연결했다. 셀 파서를 통합해 독립 `-`는 결측, 붙어 있는 음수 부호와 괄호 손실은 실제 음수로 구분한다. 절댓값 일괄 변환은 하지 않는다.
2. 최신값·연도별 이력이 서로 다른 파서를 사용했고, 항목별로 다른 표를 fallback할 수 있었다. 동일 손익표/재무상태표 단위에서 함께 추출하며 선택한 표의 누락 항목을 다른 표로 채우지 않는다. 헤더의 빈 연도 열도 유지한다. 최신 결산연도 결측, 연도 역순, 추가 그래프 숫자, 열 수 불일치를 방어한다.
3. 표와 그래프가 나란히 있는 이미지 PDF는 전체 페이지 OCR에서 숫자와 계정명이 섞인다. 제목 위치와 표선을 감지한 보조 OCR을 별도 모듈에서 실행하며 원문 본문과 식별·인증정보는 교체하지 않는다. 서로 다른 두 OCR 방식에서 제목·단위·연도 열·계정별 셀 값이 일치할 때만 근거로 사용한다.
4. 대표자명은 기존에 문서 어디에서든 `대표자명` 라벨을 `대표자`보다 우선했다. 이제 대상 업체의 표지/개요 값을 비교하고 뒤쪽 거래처·재무표의 대표자를 사용하지 않는다. 값이 충돌하면 공란과 확인 경고를 반환한다.
5. 짧은 대문자 약어가 OCR 대표자로 인식되면 추가 OCR을 한다. 서로 일치하는 한글/일반 영문명 근거가 없으면 자동 확정하지 않는다. `Kim`, `Lee` 등 정상 영문명은 지원하며, 실제 이름이 대문자 2~4자뿐인 경우에는 원문 확인 후 직접 입력할 수 있다. 특정 오인식 문자열만 하드코딩해 다른 이름으로 치환하지 않는다.
6. 한글 OCR 사전 누락 시 영어만으로 조용히 진행하지 않도록 사전을 확인한다. Windows 한글 경로가 포함된 안내문 디코딩 문제도 처리한다.
7. 대표자 미확인과 재무 출처·결산연도 경고를 등록 화면에 구체적으로 안내한다. 재무 검증 경고가 있으면 기본정보만 저장이 기본이며, 원문 확인란을 선택한 경우에만 재무값도 반영한다.
8. 별도 재무 스냅샷에서 미확인 대표자 등 기본정보가 기존 식별정보를 지우지 않게 한다. 고객 DB의 기존 공란 유지 및 명시적 갱신 동의 흐름은 유지한다.

## 사용 방법

1. 기업등록에서 같은 PDF를 다시 분석한다.
2. 대표자명과 추가 기업정보·재무·인증정보를 원문과 비교한다. 금액 표시 단위는 원이다.
3. 대표자 확인 경고가 있으면 원문에 기재된 이름을 직접 입력한다. 공란을 선택하면 이미 저장된 이름은 유지된다.
4. 재무표 출처·연도 경고가 있으면 원문을 확인한 후에만 재무 포함 확인란을 선택한다. 선택하지 않으면 기본정보·인증정보만 반영한다.
5. 기존 기업이면 정보 갱신 동의 후 저장한다. 배포만으로 과거에 저장된 잘못된 값이 바뀌지는 않는다.

## 알려진 제한

- OCR은 모든 문서 레이아웃의 정확성을 보장하지 않는다. 두 방식이 일치하지 않으면 추정값을 만들지 않는다.
- 같은 PDF의 MY재무 표와 요약 재무표가 서로 다른 값을 포함할 수 있다. 요약표를 우선하고 선택 출처를 표시하며, 항목마다 섞지 않는다.
- 이번 변경은 재무 스냅샷 전체 버전관리·다른 결산연도 간 클라우드 병합 방식까지 재설계하지 않는다. 기존 금액이 있는 고객의 갱신은 반드시 원문·결산연도 확인 후 수행한다.
- 실운영에서 짧은 대문자 대표자명이 생성된 OCR 원문은 확보하지 못했다. 잘못된 라벨 우선순위와 검증 누락은 재현했으며, 제출된 PDF의 수정 후 결과를 별도로 대조한다.

## 배포·롤백

기능 브랜치의 명시된 파일만 커밋해 GitHub PR 검사 후 main에 병합한다. GitHub 연동 Railway 배포 결과와 HTTP 상태를 확인한다. DB 마이그레이션·고객 파일 일괄 갱신은 하지 않는다. 롤백은 이 패치 코드만 revert/이전 Railway 배포 선택으로 수행하고 고객정보·Storage를 삭제하지 않는다. 이전 버전의 부호 버그가 재발하므로 롤백 중 PDF 재등록은 주의가 필요하다.

덮어쓰기 ZIP에는 변경 파일만 기존 경로로 넣으며 상위 폴더, `.git`, 고객 파일은 포함하지 않는다. BAT는 로컬 검증만 수행한다. 최신 main에 이미 배포된 경우 패치를 다시 적용하거나 중복 커밋하지 않는다.

```bash
git status
git add .
git commit -m "fix: verify CRETOP representative and financial table values"
git push origin main
```
