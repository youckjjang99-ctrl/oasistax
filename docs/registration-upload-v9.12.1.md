# 기업등록 오류 수정 및 CRM 개선 검토

2026-09-09 · `v9.12.1-registration-upload`

상태: 코드 수정·관련 로컬 테스트 완료. 운영 배포 및 운영 DB 변경은 하지 않았습니다.

## 1. 등록 오류 원인과 검증

첨부한 크레탑 보고서는 17쪽 전체가 이미지형입니다. 기존 pypdf 텍스트 추출은 본문을 읽지 못했지만, 빈 항목이 들어 있는 딕셔너리를 정상 결과로 취급했습니다. 그래서 기본정보가 모두 비어 있어도 ‘분석 완료’가 표시됐습니다. 재무자료가 없다는 사실 자체가 등록 실패 원인은 아닙니다.

PDF 텍스트 추출과 렌더된 기업개요 페이지를 함께 확인한 뒤, 필요한 페이지만 한국어 OCR로 읽도록 수정했습니다. 문서 내용은 데이터로만 취급했으며 외부 AI나 수집 API로 전송하지 않았습니다.

실제 원본을 앱과 동일한 subprocess 경로로 재검증한 결과:

| 확인 항목 | 결과 |
|---|---|
| 처리 페이지 | 17 / 17쪽 |
| 업체명·대표자·사업자번호·법인번호 | 모두 추출 확인 |
| 주소·설립일·업종·기업유형 | 모두 추출 확인 |
| 파일명과 업체명 일치 | 확인 |
| 사업자번호 길이 | 정상 |
| 종업원수 | 원문에 없어 공란 유지 |
| 주요 재무값 6개 | 모두 미확인/공란 유지 |
| 재무연도 이력 | 0개, 임의 생성 없음 |
| 분석 오류·경고 | 없음 |

로컬 소요시간은 단독 실행 약 18~19초, 다른 검증이 동시에 진행된 환경에서 약 62초였습니다. 운영 서버 성능과 문서 상태에 따라 달라질 수 있습니다.

추가로, 대상 기업의 재무표가 없는 경우 업종 비교표의 다른 기업 매출액을 잘못 읽을 수 있던 fallback 경로를 발견해 제한했습니다. 숫자가 없다는 이유로 다른 행·다른 기업·이전 연도의 수치를 채우지 않습니다.

## 2. 기업등록 화면 변경

1. **새 기업 등록 / 등록기업에 자료 추가** 중 하나를 먼저 선택합니다.
2. 새 기업은 법인 크레탑 PDF / 개인사업자 신고서의 기존 등록 방식을 유지합니다.
3. 법인 등록은 **업로드·분석 → 기본정보 확인 → 저장**으로 진행합니다. 업체명·대표자·번호·주소·업종을 먼저 보여주고, 추가 기본정보·재무·인증정보와 매칭설정은 접힌 영역에 배치합니다.
4. 부분 OCR 결과의 기본정보는 직접 보정할 수 있습니다. 업체명과 10자리 사업자등록번호가 확인되지 않으면 저장하지 않습니다.
5. 이미 등록된 기업은 별도 갱신 동의를 받아 반영합니다. 공란은 기존 값을 유지하고, 검토한 기본정보 수정값은 로컬에도 반영합니다.
6. 파일을 교체하거나 제거하면 이전 파일의 결과·수정값·중복 확인·매칭설정이 초기화됩니다.
7. 자료 추가는 기업을 먼저 선택해야 합니다. 첫 번째 기업을 자동 선택하지 않습니다. 기업별 기존 자료 현황은 요청할 때만 읽습니다.
8. 녹음, 등기, 가입자명부, 정관, 연구개발 인정서, 세무조정 자료와 메모 기능은 유지합니다.
9. 저장 후 해당 기업의 자료 추가로 이동하거나 최신 누적 엑셀을 내려받을 수 있습니다.

분석은 고객 저장과 구분됩니다. 분석 버튼만으로 고객, 재무 스냅샷 또는 PDF 첨부 연결을 갱신하지 않습니다. 클라우드 동기화가 확인되지 않으면 로컬 저장 상태와 확인 필요 경고를 표시합니다.

## 4. 테스트와 미완료 검증

- 신규 파서 20개 + 신규 등록/UI 27개 + 기존 관련 회귀 67개 = **114개 통과**.
- 관련 기존 회귀: 기업자료 등록, 고객정보 통합, 클라우드 식별번호 연결, 문서 연결, 크레탑 재무 매핑, 업로드 보안, CRM 캐시, 대표자 PDF, 중복 영업배정, 고객 보관상태, 컨설팅 읽기 전용 화면.
- 익명 고객을 실제 임시 엑셀에 저장한 뒤 재저장했을 때 행이 1개로 유지되고 재무·인원 미확인 값은 공란으로 남는 것을 확인했습니다.
- 분석만으로 저장되지 않음, 기존 고객 동의 없는 갱신 차단, 클라우드 실패 안내, 이전 파일 결과 초기화, 기업 선택 전 자료 조회 미실행을 검증했습니다.
- 파서·UI 모듈 문법검사, `git diff --check`, 개인정보 유입 검사 통과.
- 실제 고객 PDF와 OCR 중간자료는 패치에 포함하지 않았습니다. 검증 fixture는 익명 합성 데이터입니다.
- **전체 프로젝트의 모든 테스트를 실행한 것은 아닙니다.** 현재 변경에 관련된 위 114개를 실행했습니다.
- **브라우저 시각 검증 미완료:** Windows 화면 도구가 현재 브라우저 URL을 신뢰할 수준으로 확인하지 못해 도구의 안전 제한에 따라 조작을 중단했습니다. 다른 방식으로 우회하지 않았습니다. Streamlit AppTest는 통과했지만 PC/모바일의 실제 배치·스크롤 최종 확인은 운영 반영 전 필요합니다.
- **운영 검증 미실시:** Railway 실제 OCR 런타임, 실사용자 저장, 운영 다운로드는 배포 승인 후 별도 스모크 테스트 대상입니다. 한국어 OCR 패키지는 기존 `packages.txt`와 `railpack.json`에 선언돼 있어 의존성 파일은 변경하지 않았습니다.
