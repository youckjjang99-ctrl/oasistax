# v9.14.16-tax-years-files

작업일: 2026-10-23 Asia/Seoul. 기준: 최신 main `edf773487f4417d928c43990951b2c62af4811bd`.

## 문제와 원인

- 과거 세무조정 분석은 `years`만 저장하고, 현재 반영 화면이 요구하는 `valuation_periods`는 저장하지 않았습니다. 이 자료가 조용히 후보에서 제외됐습니다.
- 표 셀에서 줄바꿈된 사업연도 날짜와 명확한 귀속연도 표기의 인식 범위가 부족했습니다.
- 세무조정 반영의 원격 조회만 최근 200개 이력으로 제한되어, 자료함에 있는 과거 업로드가 반영 화면에는 없을 수 있었습니다.
- 자료함에 업로드 원본과 분석·계산 이력이 섞여 있었고 다운로드가 찾기 어려웠습니다.

## 변경

1. 사업연도 라벨에 인접한 날짜 셀·귀속연도를 보수적으로 인식합니다. 작성일·법개정일·파일명만으로 사업연도를 확정하지 않습니다.
2. ‘사업연도 확인이 필요한 업로드’에서 원본파일을 선택하고 실제 종료연도·시작일·종료일을 명시적으로 확인할 수 있습니다. 확인정보는 새 분석버전과 기존 고객이력에 보존합니다. 원본 bytes, 자료 ID, SHA, 최초등록일과 기존 분석은 유지합니다.
3. 수동 기간 복구는 금액을 자동 채우지 않습니다. 기존 당기순이익·과세표준·법인세비용을 법정 순손익액으로 대신 쓰지 않습니다. 법정 구성항목·기간·주식수·연환산·법령 검토는 기존 반영 절차를 그대로 사용합니다.
4. 저장 잠금 안에서 다시 검사하여 동시에 완료된 정상 분석을 수동 복구로 덮지 않습니다. 원격 이벤트 순서가 바뀌어도 정상 추출 사업연도는 금액이 없는 수동 기간보다 우선합니다. 양쪽 버전은 유지합니다.
5. 명시적 세무조정 조회도 소유자·기업 서버 필터를 유지한 전체 페이지 조회로 변경합니다. 일반 화면 탐색 시 원격 조회를 추가하지 않습니다.
6. ‘자료함’과 ‘이미 등록한 자료 현황 보기’는 업로드 파일 중심으로 통일합니다. 반복 분석은 같은 원본으로 묶고 파일명·유형·형식·최초등록일·원본 상태를 보여줍니다. 분석 JSON·계산 이력은 이 두 화면에서만 숨기며 삭제하지 않습니다.
7. 선택한 파일 하나만 지연 다운로드 준비합니다. 준비한 파일은 사용자·업체·파일·revision 범위에만 보관하고, 소유자·업체·원본 변경 시 폐기합니다. 경로범위·SHA 검증과 짧은 비공개 서명 링크를 유지합니다.
8. 배포 전 운영 보존 검증에서 발견한 `InvalidKey` 호환 문제를 보완합니다. 한글 원본 파일명은 메타데이터·다운로드 이름에 그대로 보존하고 내부 Storage 경로는 ASCII 해시·UUID·확장자만 사용합니다. 기존 경로와 원본은 변경하지 않습니다. 비공개 서명 URL의 토큰을 유지하면서 다운로드 쿼리에 원본 파일명을 인코딩해 첨부파일로 받을 수 있게 합니다.

## 영향과 데이터 보존

- Supabase 테이블·컬럼·인덱스·RLS 변경 및 마이그레이션 SQL 없음.
- ID·company_uid·고객자료·원본·분석·상담·계산 이력 삭제 없음.
- 세법 계산식, 인증·회원가입·권한, Tilko·경정청구 수집 API, 전화번호 수집기 변경 없음.
- 구현 테스트는 합성 자료·모의 클라우드만 사용합니다. 운영 배포 보존 단계에서는 별도 사용자 승인을 받아 원본 복사, 비공개 원본 메타·링크 등록과 확인 이력 추가만 수행했습니다. 고객 핵심정보·재무 수치·평가값은 변경하지 않았습니다.
- 운영의 비공개 원본보관 기능이 비활성이었으므로 별도 승인 후 원본 보존을 먼저 수행하고 CRM의 자동보관 플래그를 활성화합니다. 과거 원본이 로컬에도 없고 클라우드에도 보관되지 않았다면 코드만으로 복원할 수 없습니다. 이 경우 ‘원본 확인 필요’와 재업로드 안내를 표시합니다.
- 사업연도 확인의 클라우드 저장 성공과 로컬 보존을 구분합니다. 저장 실패를 클라우드 완료로 안내하지 않습니다.

## 사용법

1. 주가평가 → 세무조정계산서 반영 → 사업연도 확인이 필요한 업로드에서 누락된 파일을 선택합니다.
2. 원본의 실제 사업연도 시작·종료일과 종료연도를 입력하고 확인합니다. ‘확인한 사업연도 저장·목록에 추가’를 누릅니다.
3. 반영할 사업연도 목록에서 해당 연도를 선택하고 법정 항목과 주식수를 검토한 뒤 반영합니다. 파일명의 연도나 다른 재무 숫자를 임의로 확정하지 않습니다.
4. 자료함 또는 이미 등록한 자료 현황 보기 → 자료유형/파일 선택 → 원본 다운로드 준비 → 다운로드를 이용합니다.

## 검증·배포·롤백

최종 회귀: 운영과 같은 Streamlit 1.59.1의 실행 파일로 35개 모듈 **667개 통과**, 실패 0(기존 PDF SWIG 사용중단 경고 5개). 동시 정상 분석·원격 이벤트 순서, 과거 200건 초과 이력, 원본 불변·업체/소유자 분리, 다운로드 지연 준비와 재실행 유지, 한글 원본의 ASCII 경로 보관과 서명 토큰·다운로드 이름 보존을 포함합니다. 개인정보·비밀키 검사 대상은 변경 파일 13개입니다. 운영 로그인 후 실제 고객 PDF 재분석을 대신 수행한 것은 아닙니다.

사용자는 변경 파일 13개의 공개 GitHub 반영·main 병합·연결 Railway 서비스 재배포와 임시 SSH 접근·원본 보존·자동보관 활성화를 승인했습니다. 승인된 변경만 반영하고, 배포 후 자료함·사업연도 선택·권한·데이터 건수를 확인합니다. 배포의 최종 결과는 별도 완료 보고로 확인합니다. DB 구조 변경이 없으므로 문제 발생 시 직전 검증 코드로 되돌리되 원본·이력·새 분석버전은 삭제하지 않습니다.

**배포 전 원본 보존:** 현재 서버에서 확인한 원본 4개와 연결 메타데이터를 비공개 백업으로 복사해 전체 재다운로드 SHA 검증을 마쳤습니다. 기업 연결 원본 1개는 기존 owner/source 링크로 개별 보존·검증하고 확인 이력을 추가했습니다. 로컬 원본 삭제는 0건입니다. 서버 로컬 원본은 재배포 때 사라질 수 있으므로 코드 반영 직전에도 변동 여부를 재점검합니다. 이미 없는 과거 원본까지 복구했다고 보고하지 않습니다. 임시 SSH 키는 작업 후 등록 해제하고 로컬 임시 복사본도 제거합니다.
