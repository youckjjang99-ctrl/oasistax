# 기업정보등록 등기 업로드 업체 연결 수정

버전: `v9.14.13-registry-context` · 작업일: 2026-10-23 Asia/Seoul

기준: GitHub main `b7e07833f77213d8ce0551372d03e5763c4c7694`

## 원인

기업정보등록 화면의 업체 선택과 등기 업로더의 활성화 조건이 달랐습니다. 선택한 기업을 전달받은 후에도 주가평가 화면의 `stock_business_no` 임시 위젯 상태를 요구했습니다. 화면 이동 시 Streamlit이 위젯 상태를 정리하고 기존 자동 로드 표시만 남으면, 업체가 선택돼 있어도 업로드가 비활성화되고 기업컨설팅에서 다시 선택하라는 안내가 표시됐습니다.

## 수정

- 기업정보등록의 기존 사용자 범위 조회에서 선택한 고객 행을 등기 업로더에 직접 전달합니다. 고객 목록 재조회와 주가평가 재무정보 자동 적용을 업로드의 선행 조건으로 사용하지 않습니다.
- 업로드 대상은 선택한 행의 사업자등록번호로 결정합니다. 전달된 대상 번호와 행의 번호가 다르거나 유효하지 않으면 업로드·분석·저장을 차단합니다. 이전 호출 방식은 동일한 사용자 범위 고객 목록에서 정확한 사업자번호로만 해석합니다.
- 파일 선택 상태를 사용자·기업별로 분리해 기업 변경 시 이전 기업의 첨부파일이 남지 않게 합니다.
- 등기 복원 및 주가평가 입력값 반영은 이미 같은 기업의 주가평가를 사용 중인 경우에만 수행합니다. 다른 기업의 평가·재무·세무조정 검토값은 변경하지 않습니다.
- 기존 PDF·법인 일치 검증, 진행 카드, 화면 재실행 후 완료 안내, 로컬 보존과 클라우드 저장 구분, 첨부자료·기업히스토리 연결을 유지합니다.

## 데이터·권한·호환

Supabase 테이블, 컬럼, RLS, 저장 경로, 고객 ID, 회사 식별키는 변경하지 않습니다. 원본·기존 자료를 삭제하거나 운영 고객 데이터를 변경하지 않습니다. 전화번호 수집기와 Tilko 호출은 수정하지 않습니다. 사용자 범위 조회는 기존 `load_registered_customers`를 유지합니다.

## 사용 방법

기업정보등록 → 등록기업에 자료 추가 → 자료를 연결할 기업 선택 → 법인등기사항증명서 → PDF 첨부 → 등기자료 분석·등록 순서로 사용합니다. 기업컨설팅에서 업체를 먼저 선택할 필요가 없습니다.

## 검증·운영 반영

신규 회귀 테스트는 주가평가를 방문하지 않은 상태, 위젯 정리 후 남은 자동 로드 표시, 다른 기업의 평가 상태, 업체 변경, 잘못된 식별값, 기존 호출 호환, 정상·부분 저장 안내를 가상 자료로 검증했습니다. 운영과 동일한 Streamlit 1.59.1 환경에서 실제 등록 화면의 업체·자료 선택, 재실행, 다른 기업 선택 후 업로더 활성화와 파일 위젯 분리를 확인했습니다.

검증 결과: 관련 기존 테스트 311개와 신규 테스트 14개, 총 325개 통과. 실제 고객 PDF를 운영에 업로드하거나 운영 고객 데이터를 변경하지 않았습니다. PDF 라이브러리의 기존 SWIG 사용중단 경고 5개는 있으나 테스트 실패는 없습니다.

GitHub 공개 업로드·main 반영 및 Railway 운영 배포는 별도 승인 후 진행합니다.
